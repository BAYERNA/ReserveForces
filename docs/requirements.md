# 요구사항 정의서 v2 (Requirements Specification)

> 2026년 「예비전력분야 혁신 아이디어」 공모전 — 혁신 서비스 개발 분야
> **예비군 동원소집 통합 관제 시스템 (가칭)**
> 부제: 규정 기반 자동판정으로 여는 무중단 동원소집 관제

## 1. 문서 개요

| 항목 | 내용 |
|---|---|
| 문서 목적 | 동원소집 통합 관제 서비스의 개발 범위와 기능·비기능 요구사항을 정의하고, 1인 개발 및 공모전 시연을 위한 MVP 기준을 확정한다. |
| 서비스명 | 예비군 동원소집 통합 관제 시스템 (가칭) |
| 공모 분야 | 혁신 서비스 개발 |
| 개발 형태 | 개인(1인) |
| 주요 사용자 | 부대 동원 담당자(관리자), 소집 대상 예비군(개인) |
| 핵심 가치 | 실시간 현황 파악, 규정 기반 판정 자동화, 예비군 정보 접근성 개선 |
| MVP 원칙 | 관제 대시보드 + 예비군 개인 화면 + 규정 기반 Rule Engine + 오프라인 시연 가능 구조 |

※ 본 문서는 공모전 제출 기획안에 기반한 개발 요구사항 초안이다. 실제 제도·훈령·법령의 수치 및 예외 조건은 개발 착수 전에 최신 공식 규정을 확인하여 Rule Engine에 반영한다.

## 2. 서비스 범위

### 2.1 목표
- 부대 담당자가 소집 대상자와 입영 진행 상황을 한 화면에서 파악할 수 있도록 한다.
- 입영 시각·대상자 정보·거리 등 입력값을 규정 기반 Rule Engine으로 처리하여 반복적인 판정 업무를 지원한다.
- 예비군이 모바일 브라우저에서 본인의 소집 정보를 쉽게 확인할 수 있도록 한다.
- 네트워크가 제한된 발표 환경에서도 핵심 기능을 안정적으로 시연할 수 있도록 시나리오 데이터를 제공한다.

### 2.2 MVP 포함 범위

| 영역 | 포함 기능 | 우선순위 |
|---|---|---|
| 인증/권한 | 관리자·예비군 로그인 및 RBAC | P0 |
| 소집 관리 | 소집 회차/부대/장소/일정 및 대상자 관리 | P0 |
| 관제 | 전체 인원, 입영 현황, 미입영, 지연/예외 현황 | P0 |
| 자동판정 | 지연입소·조기퇴소 등 규칙 기반 판정 프레임워크 | P0 |
| 예비군 화면 | 소집통지, 일정, 장소, 개인 상태 조회 | P0 |
| 시나리오 | 정상/지연/예외/대규모 입영 데이터 재생 | P0 |
| 감사/이력 | 판정 및 상태 변경 이력 기록 | P1 |
| 대시보드 통계 | 시간대별 입영률·처리 현황 | P1 |

### 2.3 MVP 제외 범위
- 실제 국방동원정보체계 DB와의 직접 연계
- 실제 개인정보·군사정보를 이용한 운영 서비스
- 외부 지도/지오코딩 API에 대한 실시간 의존
- AI 챗봇의 실서비스 연동
- 영상 기반 얼굴인식·신원확인
- 실제 문자·카카오톡·푸시 알림 발송

## 3. 사용자 및 권한

| 역할 | 주요 목적 | 접근 범위 |
|---|---|---|
| 관리자(부대 담당자) | 소집 회차 관리, 대상자 현황 관제, 판정 결과 확인 및 예외 처리 | 관리자 전체 기능 |
| 예비군 | 본인 소집 정보와 현재 입영 상태 확인 | 본인 데이터만 조회 |
| 시연 관리자 | 발표용 시나리오 실행 및 초기화 | MVP 시연 전용 기능 |

권한 원칙: 예비군은 타인의 개인정보를 조회할 수 없으며, 관리자 기능은 인증된 관리자 역할에만 노출한다.

## 6. Rule Engine 요구사항

핵심 원칙은 '규정을 코드에 하드코딩하는 것'이 아니라 '규정의 기준·조건·예외를 데이터/규칙으로 관리하고 판정 근거를 남기는 것'이다.

| 구성 | 요구사항 |
|---|---|
| 입력 | 예정 입영 시각, 실제 입영 시각, 대상자 정보, 거리 등 판정에 필요한 값 |
| 규칙 | 규정별 기준값, 적용 조건, 예외 조건, 활성화 여부, 버전 |
| 판정 | NORMAL / DELAY / EXCEPTION 등 표준화된 결과 코드 |
| 근거 | 사용된 입력값·규칙 ID·규칙 버전·판정 시각·결과를 저장 |
| 예외 | 데이터 누락, 규정 적용 불명확, 추가 확인 필요 시 자동 확정하지 않고 담당자 확인 상태로 전환 |
| 변경 대응 | 향후 제도 변경 시 서비스 전체를 수정하지 않고 규칙만 변경할 수 있도록 설계 |

주의: 기존 기획안의 '1시간', '100km' 등의 수치는 공모전 기획 단계의 예시로 취급하고, 실제 구현값은 최신 공식 규정 검증 후 확정한다.

## 13. 수용 기준 (Acceptance Criteria)

1. 관리자로 로그인하면 관리자 대시보드가 표시되고, 예비군 계정으로는 관리자 기능에 접근할 수 없다.
2. 대시보드의 전체 대상자 수와 목록의 대상자 수가 일치한다.
3. 대상자의 입영 시각을 변경하면 관련 Rule Engine을 실행하여 판정 결과가 갱신된다.
4. 판정 결과 화면에서 적용 규칙과 판정에 사용된 입력값을 확인할 수 있다.
5. 예비군 화면에서는 본인의 소집 정보만 조회할 수 있다.
6. 정상·지연·예외·대규모 입영 시나리오를 발표용 데이터로 재현할 수 있다.
7. 인터넷 연결을 차단한 상태에서도 핵심 시연 흐름을 완료할 수 있다.
8. 시연 종료 후 초기화 기능을 통해 동일한 시나리오를 다시 실행할 수 있다.
9. 실제 개인정보 대신 가명 및 더미 데이터만 사용한다.
10. 규정 기준 변경을 고려하여 판정 로직의 기준값과 버전을 독립적으로 관리할 수 있다.

## 17. 최종 MVP 정의

MVP의 한 문장 정의: "부대 담당자가 소집 현황을 실시간으로 관제하고, 입영 데이터를 규정 기반 Rule Engine으로 판정하며, 예비군은 모바일 웹에서 자신의 소집 정보를 확인할 수 있는 오프라인 시연 가능한 통합 관제 서비스."

개발 완료의 기준: 관리자 로그인 → 대시보드 → 대상자 상세 → 입영 데이터 입력 → 자동판정 → 판정 근거 확인 → 대시보드 반영 → 예비군 개인 화면 확인까지 하나의 흐름이 끊김 없이 동작하고, 동일 흐름을 인터넷 없이 재현할 수 있어야 한다.
